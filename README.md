# Преферанс — сочинка

Браузерная игра на троих: человек против двух компьютерных соперников. Отдельный проект, визуально продолжающий Solo Spades: тёмная палитра, золотые акценты, светлые карты и расположение для трёх игроков.

Игра: https://eugenetsuprun.github.io/preferans/

## Возможности

- Торговля с приоритетом старшей руки («здесь»), постоянным пасом и мизером первой личной заявкой.
- Открытый прикуп, закрытый снос двух карт, заказ контракта не ниже выигранной торговли.
- Ответственный жлобский вист, полвиста на шестерной и семерной, возврат полвиста, игра в светлую и в тёмную.
- При открытом висте обе руки защитников ведёт единственный вистующий. При мизере защитники открываются после первого хода; человек управляет обеими руками защиты, если он защитник.
- При открытой игре на экране видны все три руки. Ваша рука остаётся внизу при ходе за партнёра; его карты выбираются в его панели. Текущий игрок указан над столом и выделен рамкой.
- Распасы: по единице в гору за взятку, за ноль — единица в пулю; прикуп задаёт масть первых двух взяток, первые три хода с первой руки.
- Автоматическая запись пули, горы, вистов, консоляции и помощи. История раздач и итоговый расчёт в вістах с нулевой суммой.
- Пуля до 10 / 20 / 30 / 50 / 100, три сложности и три темпа. Сложность и темп меняются во время партии.
- Автосохранение на этом устройстве; после перезагрузки — кнопка продолжения. Подсказок и объяснений ходов нет.
- Карты-кнопки как в Spades: отдельные квадратные плитки рядами по мастям, без перекрытий, с областью нажатия не меньше 44×44 px.
- Постоянно видны пуля, гора и текущий итог каждого игрока; стоимость контракта и прогресс взяток указаны отдельно.
- PWA: установка в отдельное окно без адресной строки, иконки для рабочего стола и офлайн-работа после первой загрузки. Обновление версии применяется по кнопке с сохранением партии.

## Договорённости

Без прогрессии распасов и ужесточения выхода, без Сталинграда. Десятерная разыгрывается для проверки без записи вистов. Мизер без прикупа и тёмные контракты не используются. Игра заканчивается, когда все три пули закрыты; сверх записи применяется помощь в пулю с десятикратными вистами, затем списание с горы. Это выбранный набор договорных правил, а не все существующие варианты сочинки.

Таблица стоимости и особенности сочинки сверены с [правилами клуба preferans.games](https://preferans.games/sochi/rules/). Договорённости доступны из настроек игры.

## Боты

Лёгкая: случайный допустимый розыгрыш. Средняя: оценка ходов на случайных допустимых раскладах. Высокая: поиск ISMCTS с общей для разных возможных раскладов историей ходов, до 1800 итераций с бюджетом 900 мс. В концовках до 15 оставшихся карт — до 128 сэмплов и ограниченный минимакс для контрактов или трёхсторонний max-n для распасов. Внутри поиска эквивалентные соседние карты объединяются для уменьшения числа ветвей. Возможные расклады учитывают публичный прикуп, мастевые отказы и мягкую оценку правдоподобия выигранной заявки. Необычные руки не запрещаются: игрок может торговаться рискованно.

Цель поиска — собственный результат в вистах по реальным правилам записи, включая ответственность вистующих, мизер и премию за ноль на распасах. Для незакрытых пуль используется эквивалентная оценка «гора минус пуля». На распасах симуляции учитывают опасные старшие карты, безопасные выходы и возможность снести старшую карту под чужую взятку. Защита мизера пытается заставить играющего взять, а защита обычного контракта учитывает карту партнёра и возможность перебития третьей рукой. Вычисления выполняются в Web Worker.

На высокой сложности торговля дополнительно проверяет 48 случайных раскладов с неизвестным прикупом и сносом. Структурная оценка руки ограничивает оптимистичные прогнозы симуляций; длинные побочные масти учитываются. При заказе контракта бот выбирает доходный обоснованный уровень, вместо автоматического предпочтения шестерной. Вист и полвиста сравниваются на 48 допустимых раскладах с учётом записи, штрафов и вероятного ответа второго защитника. Боты не используют настоящие закрытые руки и неизвестный прикуп при выборе действий; это проверяется тестами. Уровень не проходил сравнительную оценку против турнирных программ. Обучена отдельная нейросетевая оценка руки; активную политику выбирает `src/bot.ts`, а экспериментальные варианты проверяются отдельно в арене.

## Разработка

Требуется Node.js 22.12+.

```sh
npm ci --legacy-peer-deps
npm run dev
npm test
npm run build
npm run simulate
npm run evaluate
```

В GitHub Actions каждый push в main запускает тесты, проверку TypeScript, сборку с базой `/preferans/` и публикацию GitHub Pages. Обычная локальная сборка использует `/`.

## Проверка

Тесты покрывают торговлю, снос, обязанность дать масть и козырь, открытый вист, полвиста, запись очков, распасы, мизер, десятерную, независимость поиска от настоящих закрытых рук, 50 полных раздач и полный розыгрыш на высокой сложности.

`npm run simulate` сравнивает новую логику с версией `b542e19` на фиксированных раздачах. По умолчанию это 12 распасных раздач с новой логикой по очереди на каждой из трёх рук и 120 проверок торговли. Для увеличения выборки: `SIM_HANDS=100 BID_HANDS=300 npm run simulate`. `BASELINE_REF` позволяет выбрать другой коммит. На распасах контроль — три старых бота; в каждой парной проверке заменяется только одна рука. При проверке торговли соперники пропускают начальную заявку; затем оба варианта торговой логики разыгрывают контракт одним и тем же старым ботом средней сложности. Это проверка первоначального входа в торговлю и выбора контракта, а не полного конкурентного аукциона. Фиксированы карты и генераторы случайных чисел; лимит времени поиска может влиять на результат на медленных устройствах.

`npm run evaluate` проводит полный конкурентный аукцион, снос, выбор контракта, вист и розыгрыш. На каждой фиксированной раздаче играют три старых бота, затем по очереди заменяется одна из трёх рук. Отдельные одинаковые стартовые позиции проверяют шестерную с козырем, семерную без козыря, мизер и распасы. Метрика — изменение результата в вистах, с поправкой на незакрытую пулю, а не частота заявок или процент выигранных контрактов. `EVAL_DEALS`, `SUITE_DEALS` и `EVAL_SEED` задают объём и независимую выборку; `EVAL_OUTPUT` сохраняет JSON. Пример: `EVAL_DEALS=48 SUITE_DEALS=12 EVAL_SEED=40001 EVAL_OUTPUT=/tmp/preferans-evaluation.json npm run evaluate`. Сравнения трёх рук одной раздачи коррелированы; положительный результат против одной старой версии ещё не означает турнирной силы.

## Исследования и дальнейшее обучение

Полный отчёт на английском: [TRAINING_REPORT.md](TRAINING_REPORT.md). Он включает принятые и отклонённые эксперименты, ограничения, результаты арены и команды воспроизведения. Сжатые данные обучения сохранены в `training/hand-value-data.jsonl.gz`.

Из литературы по преферансу следует, что торговлю надо оценивать относительно альтернативы — распасов, а не только вероятности сыграть шестерную. Статья [В. Г. Ильичева](https://www.mathnet.ru/php/getFT.phtml?jrnid=mo&paperid=664&what=fullt) разбирает именно этот выбор; её численные оценки относятся к «Ростову», поэтому здесь используются собственные правила сочинки. Книга [О. Скуратова](https://thelib.ru/books/skuratov_o/preferans_istoriya_strategiya_taktika-read-5.html) иллюстрирует важность позиции, сохранения переходов, совместной защиты и осмысленного виста. Это направления для тактических тестов, а не набор безусловных правил для любой раздачи.

Работа [Buro et al., 2009, о Skat](https://webdocs.cs.ualberta.ca/~nathanst/papers/skat.pdf) показывает пользу обучаемой оценки торговли и вывода о скрытых руках из действий соперников. [Cowling, Powley & Whitehouse, 2012](https://eprints.whiterose.ac.uk/id/eprint/75048/1/CowlingPowleyWhitehouse2012.pdf) описывают ISMCTS и проблему несовместимых планов в отдельных раскладах; на их алгоритме основана текущая общая поисковая история. [Rebstock et al., 2019](https://arxiv.org/abs/1905.10907) отдельно исследуют обучение торговли и выбора игры по человеческим партиям. Применимость этих подходов к преферансу — инженерная гипотеза, которую здесь проверяет арена.

Первый пилот уже обучен с учителем на исходах 24 000 симуляций игры поисковых ботов средней сложности. Из них 19 200 раздач используются для обучения, 2400 — для выбора модели, ещё 2400 — для проверки. Вход — 80 признаков своей руки, собственного сноса, козыря и позиции; скрытых рук соперников во входе нет. Масти приводятся к каноническому порядку, чтобы одна комбинация рангов переносилась между мастями. Сеть 80 → 96 → 48 → 11 выдаёт распределение количества взяток, а не одну категоричную оценку. Проверочная средняя абсолютная ошибка — около 0,89 взятки. Это результат прогнозирования партий учителя, а не доказательство превосходства в игре.

В `src/ai-trained.ts` модель сравнивает нормальные контракты по ожидаемому результату и ранжирует короткий список сносов; для очень сильных редких рук и мизера сохраняется поисковая логика. Сравнение сноса отдельно от выбора контракта доступно через `CANDIDATE_EXPORT=botActionDiscard`. Первые 6000 примеров дали модель, которая проиграла поисковому боту в арене; она не была активирована. Итоги обучения находятся в `training-results.json`, результаты арены — в `simulation-results.json`.

Воспроизведение: установить Python-зависимости из `scripts/requirements-training.txt`, затем выполнить `npm run training:data` и `npm run training:fit`. `TRAIN_GAMES`, `TRAIN_WORKERS`, `TRAIN_SEED` и `TRAIN_DATA` задают объём, параллелизм, раздачи и путь к данным. Текущая модель использует 6000 раздач с seed от 1000001 и 18000 — от 2000001; два файла объединяются перед обучением. Метаданные содержат SHA-256 данных. Для проверки кандидата: `CANDIDATE_MODULE=ai-trained EVAL_SEED=80001 EVAL_DEALS=24 SUITE_DEALS=0 npm run evaluate`. Для сравнения с предыдущей локальной версией `BASELINE_FILE` задаёт сохранённый файл `ai.ts`. По умолчанию эталон — исходная версия `b542e19`.

Следующий этап — полноценное self-play обучение против смеси зафиксированных старых версий с отдельной проверкой торговли, виста и трёх типов розыгрыша. Подходящий ориентир — [DouZero](https://proceedings.mlr.press/v139/zha21a.html), обучавший трёхстороннюю карточную игру через self-play. Текущий пилот — обучение на результатах симуляций; нейросеть пока не проходит цикл самостоятельной игры и обновления по собственным результатам. Нельзя переносить гарантии сходимости двухстороннего покера на трёх игроков с меняющимися союзами; [Deep CFR](https://proceedings.mlr.press/v97/brown19b.html) полезен как исследовательский ориентир, но не обещает здесь готового решения.

Арена уже умеет экспортировать исходные примеры: `TRAJECTORIES=/tmp/preferans-selfplay.jsonl npm run evaluate`. Каждая строка содержит наблюдение игрока, выбранное действие, версию политики, итоговый результат и публичное количество взяток. Закрытые руки, чужой снос и неизвестная часть прикупа отсутствуют во входном наблюдении. Все строки одной раздачи должны попадать только в одну из обучающей, проверочной или тестовой выборок; разделять строки случайно нельзя. Эти журналы — материал для обучения, а не уже обученная модель.

## Установка приложения

Откройте игру в Chrome или Edge и нажмите «Установить», когда браузер предложит установку. На iPhone или iPad: Safari → «Поделиться» → «На экран Домой». Запускайте установленную иконку: `display: standalone` открывает игру без адресной строки. Для подготовки офлайн-режима требуется один раз загрузить игру с интернетом. В офлайн-кэш входят страница, стили, шрифты системы, иконки и Web Worker соперников.
